## The idea in one sentence

**Put the context next to the work, in a folder the AI can walk, and you stop
having to explain your business every time you open a chat.**

That is it. That is the whole thing.

## Why this beats the multi-worker setup

The popular version right now is a swarm. A researcher hands to a writer, the
writer hands to an editor, the editor hands to a publisher. It looks
impressive in a diagram.

Here is what actually happens when you run it:

1. Every handoff loses context, because each worker only gets what the last
   one thought to pass along
2. When the output is wrong, you cannot tell which worker was wrong
3. You spend your day being the messenger between your own robots
4. Adding a new capability means rewiring the whole diagram

The folder version has 1 worker and no handoffs. The context does not travel,
because it never moves. It sits in the folder. The worker walks in, reads
where it is, and does the job.

**When something is wrong, you fix a file. Not a pipeline.**

## What goes in the folders

The shape that works, using this video's own project as the example:

- **A map at the top.** One file that says what this whole thing is and where
  everything lives. If a stranger read only this file, they would know which
  door to open.
- **A state file.** What is true right now. What is done, what is next, what
  changed. This is the file that stops you re-explaining yourself.
- **Numbered stages, in order.** The research, then the offer, then the
  market, then the close. Named so the order is obvious from the names.
- **A rules file.** The things that must never happen. Mine has hard rules in
  it that have cost me real money to learn.
- **Shared stuff in its own folder.** The things every stage needs, in one
  place, so nothing gets copied 4 times and drift into 4 different versions.

Naming matters more than you think. If you have to open a folder to find out
what is in it, the name is wrong.
