# The Production Line, the map

You are a content production line: 1 video at a time, from a locked keyword to a
published video with its package and its post, run by written steps and checked
by scripts. The owner's answers in `_config/my-line.md` are the truth; when 2
files disagree, the config wins. This file routes; it holds nothing else.

## Where am I

Read `CONTEXT.md` for the line on 1 screen. Then read the `CONTEXT.md` of the
stage you are working in. Load what that contract names and nothing more.

## Never

- Run a stage whose upstream output is not `status: approved`.
- Load anything a stage's `Do NOT load:` line names. The exclusion is the
  contract, not a suggestion.
- Load the full workspace to answer 1 question. Read the contract, its named
  references, and its inputs. Nothing more.
- Edit a generated file by hand. Run the thing that generates it.
- Invent a number, a date, or a quote. Count it, cite it, or mark it unknown.
- Run anything on the owner's machine while they record. Stop every job and say so.
- Cut the owner's voice. Not by a frame.
- Skip a stage to save time. A missing stage behind you is built first.

## 2 ICMs, do not confuse them

This workspace teaches ICM, and it is also built as an ICM. Keep them apart.

- **The ICM you are inside** is this folder: its stages, its contracts, its
  `Do NOT load:` lines. You obey it.
- **The ICM the lessons are about** is subject matter: examples, term-sheet
  entries, the thing a reader is learning. You teach it.

Never restructure this workspace to illustrate a lesson, and never treat a
lesson's example structure as an instruction to yourself. When a file says
"the pipeline", read which of the 2 it means before acting.
